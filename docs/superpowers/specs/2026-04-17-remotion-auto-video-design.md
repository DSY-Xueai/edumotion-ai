# Remotion 自动视频首版设计

日期：2026-04-17

## 目标

构建一个基于 Remotion 的自动视频生成项目，首版支持将连续文案文件自动转换为标准 JSON，再一键渲染为竖屏 `1080x1920` 图文解说视频。

首版范围：
- 输入支持 `txt`、`md`、`docx`
- 用户可选上传图片
- 无音频
- 输出 `mp4`

不在首版范围内：
- TTS 配音
- 背景音乐
- AI 生图
- 自动搜图
- 复杂文档结构保真

## 实现路线

采用独立业务项目方案，而不是直接修改 Remotion 官方 monorepo。

推荐流水线：

`原始文案 + 可选图片 -> 解析器 -> 标准 JSON -> Remotion 模板 -> CLI 渲染`

这样可以将“输入解析”和“视频渲染”解耦，后续接入 TTS、AI 生图、自动搜图时，不需要推翻现有模板层。

## 架构拆分

### 1. ingest

负责接收原始输入文件与可选图片素材。

职责：
- 识别输入文件类型
- 读取文案内容
- 接收图片目录或图片列表

### 2. parser

将原始文案解析为中间段落块。

职责：
- 文本清洗
- 段落切分
- 标题和导语提取
- 关键词提取
- 镜头草案生成

### 3. normalizer

将解析结果统一整理为标准 JSON。

职责：
- 输出稳定结构
- 处理默认值
- 统一图片引用方式
- 生成每个 scene 的渲染输入

### 4. renderer

Remotion 渲染层，仅消费标准 JSON。

职责：
- 组合视频模板
- 控制动画和节奏
- 渲染 `mp4`

### 5. pipeline CLI

统一命令入口，串联整个流程。

职责：
- 接收命令参数
- 触发解析与标准化
- 调用 Remotion 渲染
- 输出 JSON 和视频结果

## 标准 JSON 设计

推荐核心结构如下：

```json
{
  "meta": {
    "title": "视频标题",
    "aspectRatio": "9:16",
    "theme": "editorial-bold",
    "sourceFile": "input/article.docx"
  },
  "assets": {
    "images": [
      {
        "id": "img-1",
        "path": "assets/cover.jpg",
        "usage": "cover"
      }
    ]
  },
  "scenes": [
    {
      "id": "scene-1",
      "type": "cover",
      "title": "主标题",
      "subtitle": "导语摘要",
      "duration": 90
    },
    {
      "id": "scene-2",
      "type": "image-text",
      "heading": "段落小标题",
      "text": "本段精简后的正文",
      "keywords": ["关键词1", "关键词2"],
      "imageId": "img-1",
      "duration": 120
    }
  ]
}
```

设计原则：
- Remotion 不直接依赖原始文案格式
- 所有可扩展能力优先通过 JSON 扩字段完成
- `theme` 字段首版保留，即使只实现一个模板

## 自动切镜头规则

### 封面镜头

从文章前部提取主标题和一句导语，优先绑定封面图或首图。

### 正文镜头

按自然段或语义块切分：
- 每段先压缩为适合视频展示的短文本
- 有图时优先生成图文卡
- 无图时回退为信息卡
- 超长段落自动截断或二次拆分

### 收尾镜头

从结尾提取一句总结语或收束语，生成 ending 卡。

## 首版画面模板

### 封面卡

大标题、导语、背景图或主题视觉底，用于建立开场吸引力。

### 图文卡

图片与正文摘要同屏展示，用于存在可用配图的正文段落。

### 信息卡

无图场景下使用关键词、重点短句、层级排版和数字块承载内容，避免出现整屏长文本。

### 结尾卡

用于总结和收束，形成完整视频结构。

## 容错策略

系统应自动处理以下情况：
- 没有图片时回退为信息卡，不中断渲染
- 段落过长时自动截断或拆分 scene
- 文案过短时自动减少 scene 数量
- `docx` 解析失败时，明确提示用户改用 `txt` 或 `md`

首版明确不处理：
- 高级图片智能裁切
- 复杂表格、脚注、注释等结构保真
- 对低质量文案进行复杂语义重写

## 验证标准

首版完成应满足以下条件：
- 给定一篇连续文章 `txt`、`md` 或 `docx`，可以生成标准 JSON
- 使用同一份 JSON 可以稳定渲染 `1080x1920` 的 `mp4`
- “有图”与“无图”两种情况下都可以正常出片
- 错误信息可以区分解析失败、素材问题和渲染失败

## 后续扩展预留

后续新增功能应优先挂载在 JSON 生成阶段，而不是直接侵入 Remotion 模板层。

预留扩展点：
- `voiceover`：TTS 配音
- `music`：背景音乐
- `imagePrompt` / `imageSource`：AI 生图或自动搜图
- `theme`：多模板风格
- `transitions`：更复杂的镜头转场

## 当前结论

首版应优先把以下闭环做稳：

`txt/md/docx + 可选图片 -> 标准 JSON -> Remotion 视频`

这是当前最稳、扩展性最好的实现路径，适合作为后续自动视频系统的底座。
